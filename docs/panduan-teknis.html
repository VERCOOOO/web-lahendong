Gambaran besar

Situs statis yang membaca spreadsheet

Tidak ada server, database, maupun proses build. GitHub Pages hanya mengirim berkas apa adanya: HTML, CSS, JavaScript, dan gambar. Semua pekerjaan terjadi di browser pengunjung: setelah halaman terbuka, JavaScript mengunduh isi Google Sheet dalam bentuk CSV, lalu menyusunnya menjadi HTML.

Pembagian tugasnya tegas:

  • Google Sheet menyimpan isi: angka, nama, teks, daftar.
  • HTML menyimpan kerangka halaman: judul, kalimat pengantar, dan wadah kosong yang nanti diisi.
  • JavaScript mengambil data dan mengisi wadah itu.
  • CSS (style.css + kelas Tailwind) mengatur rupa.

Pustaka luar yang dimuat dari CDN hanya empat: Tailwind (kelas utilitas seperti mt-4), Lucide (ikon), PapaParse (membaca CSV), dan Chart.js (grafik, hanya di halaman Penduduk). Tidak ada npm, jadi tidak ada yang perlu dipasang.

Alur data

Dari sel sheet sampai kartu di layar

Contoh: pengunjung membuka wisata.html.

  1. Browser memuat halamanHTML berisi <div id="grid-wisata"> yang masih kosong, lalu skrip dimuat berurutan: data.js → data-contoh.js → ui.js → komponen.js → halaman/wisata.js.
  2. ui.js menggambar kerangkaHeader, footer, breadcrumb, dan info kantor (data-profil) diisi saat DOMContentLoaded.
  3. wisata.js memanggil isiDariData()Wadah langsung menampilkan "Memuat data…", lalu ambilData("wisata") dipanggil.
  4. ambilData() mengunduh CSVAlamatnya docs.google.com/spreadsheets/d/{ID}/gviz/tq?tqx=out:csv&sheet=wisata. Google mencari tab berdasarkan nama. Batas waktu 15 detik.
  5. PapaParse membaca CSVBaris pertama menjadi nama kolom: "Jumlah KK" → jumlah_kk. Setiap baris menjadi satu objek: { nama: "Danau Linow", foto: "…", … }, ditambah _baris = nomor barisnya di sheet.
  6. Data dirapikanKolom diperiksa terhadap SKEMA, kolom yang hilang diisi kosong, setiap nilai di-escape agar aman untuk HTML, baris yang kolom pertamanya kosong atau bertanda tampil = Tidak dibuang (saringBaris), dan tab tanpa kolom id diberi kode dari kolom pertamanya (beriKode). Hasilnya disimpan di memori, jadi tab yang sama tidak diunduh dua kali.
  7. Fungsi render membuat HTMLdata.map(kartuWisata).join("") menghasilkan satu string HTML yang dipasang ke wadah.
  8. Sentuhan akhiraturKolom() menyusun kolom sesuai jumlah kartu, Lucide mengganti <i data-lucide> menjadi ikon, dan animasi muncul diaktifkan.
Bila langkah 4–6 gagal (sheet privat, tidak ada internet, nama tab salah), wadah menampilkan pesan ramah seperti "Daftar destinasi belum bisa dimuat saat ini", dan penyebab teknisnya dicatat di konsol browser dengan awalan [data].

Mode data contoh: bila PAKAI_DUMMY = true di data.js, langkah 4–5 dilewati dan data diambil dari objek DATA_DUMMY di data-contoh.js. Langkah 6 tetap dijalankan persis sama, jadi tampilan kedua mode identik. Mode ini berguna untuk mencoba perubahan kode tanpa internet.

Fungsi kunci

Tujuh fungsi yang menopang semuanya

SKEMAdata.js

Daftar kolom setiap tab, berurutan seperti di sheet. Kolom pertama adalah kunci baris: baris yang kuncinya kosong diabaikan, begitu juga baris yang kolom tampil-nya "Tidak" (cara admin menyembunyikan baris). Tidak ada kolom id di tab mana pun: setiap baris mendapat id otomatis dari kolom pertamanya lewat kodeDari() — "Danau Linow" → danau-linow (nama kembar diberi akhiran -2). Tidak ada pula angka yang ditulis dua kali: tab statistik dan kolom jumlah_jiwa sengaja tidak ada; semua total dihitung ringkasPenduduk() dari tab lingkungan. Nama kolom yang hilang di sheet hanya memunculkan peringatan dan terbaca kosong. Namun bila kolom pertama hilang, tab dianggap salah dan data ditolak.

const SKEMA = {
  profil:  ["kunci", "nilai", "keterangan"],        // tab kunci-nilai
  wisata:  ["nama", "tampil", "foto", "ringkas", "deskripsi", …],
  aparat:  ["jabatan", "nama", "atasan", "nomor", "foto"],   // atasan = jabatan
  …
};
ambilData(namaTab) → Promise<Array>data.js

Satu-satunya pintu masuk data. Mengembalikan array objek yang sudah rapi dan aman. Setiap tab hanya diunduh sekali per kunjungan halaman (disimpan di tembolokData); bila gagal, simpanan dihapus agar pemanggilan berikutnya mencoba lagi.

const wisata = await ambilData("wisata");
// [{ id: "danau-linow", nama: "Danau Linow", foto: "…", ringkas: "…", _baris: 2, … }, …]
isiDariData(wadah, tab, render, opsi)komponen.js

Pola baku setiap blok data. Hampir semua isi situs dipasang lewat fungsi ini, sehingga penanganan memuat, kosong, dan gagal seragam di mana-mana.

  • tab: satu nama tab, atau array nama tab (render lalu menerima array hasil).
  • render(data): mengembalikan string HTML. String kosong berarti "tidak ada data".
  • opsi.kosong / opsi.gagal: pesan. Isi null agar wadah dihapus diam-diam (untuk blok pelengkap).
  • opsi.setelah(data): dijalankan setelah HTML terpasang, misalnya untuk menggambar grafik.
isiDariData(document.getElementById("grid-wisata"), "wisata",
  (data) => data.map((item) => kartuWisata(item)).join(""),
  { gagal: "Daftar destinasi belum bisa dimuat saat ini." }
);
aturKolom(wadah)komponen.js

Menghitung jumlah kolom dari jumlah kartu yang tampil, lalu menyimpannya di variabel CSS --kolom dan atribut data-kolom. Dipanggil otomatis oleh isiDariData() untuk setiap .grid-adaptif dan .deret-statistik, dan oleh penyaring Galeri setiap kali kartu disembunyikan. Rinciannya di bagian Grid adaptif.

urlFoto(), folder foto Drive, FOTO & gambar(tab, item)data.js · komponen.js

Kolom foto (wisata, aparat, galeri) dan kunci foto_hero diatur dari sheet. urlFoto() menerima tautan berbagi Google Drive (…/file/d/ID/view, open?id=ID) dan mengubahnya menjadi drive.google.com/thumbnail?id=ID&sz=w800 — gambar seukuran yang dibutuhkan, bukan berkas aslinya. Tautan https lain dipakai apa adanya; nama berkas biasa dianggap berada di img/. Tautan folder ditolak.

Folder foto Drive. tools/sinkron-foto.gs (Apps Script di spreadsheet, pemicu tiap 10 menit) menulis isi folder "Foto Situs Lahendong" ke tab foto (nama_file, folder, id_drive, diubah) dan membagikan setiap gambar. Di situs, siapkanFotoDrive() memuat tab itu sekali per kunjungan — isiDariData() menunggunya sebelum render — dan susunIndeksFoto() menyusun indeks subfolder → kode nama berkas (berkas ganda: yang terbaru). kodeFotoDrive() menentukan nama yang dikenali per tab: wisata/galeri = kode baris; aparat = jabatan, nama, atau nama tanpa gelar (namaTanpaGelar()); kkt = NIM atau nama; lingkungan = nama orang. Tanpa kunci API: situs hanya membaca tab spreadsheet seperti biasa.

sumberFoto() menyusun urutan sumber: kolom foto → foto dari folder Drive (fotoDrive()) → foto cadangan di registri FOTO (menurut kode baris) → placeholder.webp. Bila satu sumber gagal dimuat (mis. foto Drive belum dibagikan), fotoBerikutnya() di onerror mencoba sumber berikutnya. Aparat memakai visualOrang(): monogram inisial selalu dirender di belakang foto, jadi bila foto gagal yang tampil monogram.

const FOTO = {
  wisata: { "danau-linow": "wisata-danau-linow.webp", … },   // kode dari nama
  aparat: { },   // menurut kode nama orang
};
isiInfoKantor()ui.js

Mengisi setiap elemen bertanda data-profil="kunci" dari tab profil, di halaman mana pun, tanpa JavaScript tambahan. Bila nilainya kosong, wadah terdekat [data-wadah-profil] dihapus, sehingga situs tidak pernah menampilkan baris kosong atau isian karangan. data-profil-tautan="tel" atau "mailto" menjadikannya tautan telepon/email.

<p data-wadah-profil>Jam layanan: <span data-profil="jam_layanan"></span></p>
escapeHtml(), teksPolos(), keAngka(), barisDari()
  • escapeHtml: setiap nilai sheet di-escape saat dirapikan, jadi tulisan <script> di sel tampil sebagai teks, tidak dijalankan. Karena itu nilai dari ambilData() aman disisipkan ke HTML.
  • teksPolos: kebalikannya, untuk konteks yang bukan HTML (judul tab browser, label grafik, URL).
  • keAngka: membaca "2235", "2.235", "7,85", "7.85" dengan benar; bukan angka → null. formatAngka menulis ulang gaya Indonesia (2.235 · 7,85).
  • barisDari: memecah sel berdasarkan baris baru. paragraf(), berbaris(), dan daftarAtauTeks() memakainya untuk mengubah satu sel menjadi beberapa paragraf, baris, atau butir daftar.
Grid adaptif

Susunan kartu mengikuti jumlahnya

Wisata, Galeri, kolom struktur aparat, lingkungan, dan kontak memakai kelas .grid-adaptif. Aturannya: bagi kartu ke baris sesedikit mungkin (maks. 4 per baris), lalu bagi rata per baris.

function hitungKolom(n, maks = 4) {
  const baris = Math.ceil(n / maks);   // 6 kartu → 2 baris
  return Math.ceil(n / baris);          // 6 / 2 → 3 kolom
}
Jumlah kartu123456789
Desktop (≥1024px)12343+23×24+34×23×3
Tablet (640–1023px)2 kolom
HP1 kolom; 2 kolom untuk kartu kecil (data-hp="2": aparat, lingkungan)

CSS-nya memakai flexbox, bukan grid biasa, agar baris terakhir yang tidak penuh bisa diletakkan di tengah. Lebar tiap kartu dihitung dari --kolom:

.grid-adaptif { display: flex; flex-wrap: wrap; justify-content: center; gap: var(--jarak); }
@media (min-width: 1024px) {
  .grid-adaptif > * { flex-basis: calc((100% - (var(--kolom) - 1) * var(--jarak)) / var(--kolom)); }
}

Pengaturan per wadah lewat atribut HTML: data-maks="3" (paling banyak 3 per baris), data-hp="2" (2 kolom di HP), dan kelas rata-kiri (baris terakhir rata kiri, dipakai di Kontak). Deret angka statistik (.deret-statistik) memakai hitungan yang sama, sehingga bila satu angka dikosongkan, sisanya tetap mengisi lebar penuh.

Layanan & struktur

Dua bagian yang dibentuk sepenuhnya oleh sheet

Layanan surat (halaman/layanan.js)

  • Kelompok: kelompokkan() mengumpulkan surat per kolom kategori, urut sesuai kemunculan pertama di sheet; surat tanpa kategori masuk "Lainnya" di akhir. Bila hanya ada satu kelompok, judul kelompok dan tombol penyaring tidak ditampilkan.
  • Isi sel → daftar: butirDari() memecah syarat dan alur per baris. Sel lama yang masih satu baris tetap terbaca: syarat dipecah di koma/titik koma, alur di tanda →.
  • Pencarian & penyaring: tiap surat menyimpan teks yang dicari di atribut data-cari (nama, kategori, syarat). terapkanSaringan() menyembunyikan surat dan kelompok yang tidak cocok, lalu menampilkan pesan bila hasilnya kosong. Kotak cari baru muncul bila surat ≥ 5.
  • Tautan langsung: kode surat (dari namanya) menjadi atribut id elemennya; bukaDariAlamat() membuka dan menggulir ke surat itu bila alamatnya layanan.html#surat-keterangan-domisili. Beranda memakainya untuk daftar surat (MAKS_LAYANAN_BERANDA = 6).

Struktur aparat (halaman/pemerintahan.js)

  • susunPohon() mengubah baris tab aparat menjadi pohon: kolom atasan berisi jabatan atasan, dicocokkan longgar oleh samaJabatan() (huruf besar/kecil & tanda baca diabaikan). Baris tanpa atasan — atau atasannya tidak ditemukan — menjadi puncak; adalahBawahan() mencegah susunan melingkar. Urutan = urutan baris.
  • renderStruktur() menggambar puncak sebagai panel pimpinan, bawahan langsungnya sebagai kolom (.cabang di dalam .grid-adaptif), dan bawahan mereka sebagai daftar staf bertingkat (daftarStaf(), rekursif).
  • Garis penghubung murni CSS. Di HP & tablet, setiap .cabang menggambar ruas garis jalur di kirinya (::after) dan ranting ke kartunya (::before). Di desktop, kelas .tersambung (dipasang bila bawahan langsung ≤ 4, jadi muat satu baris) menggambar garis turun, rel mendatar, dan garis ke tiap kolom. Lebih dari 4 kolom → kartu membungkus ke baris berikut tanpa garis.
  • Kartu lingkungan menulis "Lingkungan 3" sebagai angka besar dan menggambar batang .porsi = jumlah jiwa dibanding lingkungan terbesar.
Sistem tampilan

Di mana mengubah rupa

  • Warna: hanya di :root pada awal style.css. Semua komponen memakai token (var(--primary), dsb.), jadi mengganti satu nilai mengubah seluruh situs. Warna grafik ada di WARNA pada penduduk.js (Chart.js tidak bisa membaca variabel CSS).
  • Huruf: Archivo (judul, angka) dan Plus Jakarta Sans (teks), dimuat di <head> setiap HTML dan diatur di --font-judul / --font-teks.
  • Kelas Tailwind vs style.css: Tailwind untuk jarak dan tata letak sekali pakai (mt-4, md:col-span-7); style.css untuk komponen yang berulang (.kartu, .tombol, .eyebrow). Tailwind dimuat belakangan, jadi pada spesifisitas yang sama kelas Tailwind yang menang. Jangan memasang kelas lebar kolom Tailwind (lg:grid-cols-4) pada .grid-adaptif.
  • Kop halaman (bidang gelap di bawah menu) punya siluet punggungan gunung di tepi bawah. Warnanya mengikuti seksi di bawahnya; tambahkan kelas tepi-putih bila seksi itu berlatar putih.
  • Aturan desain lengkap: DESIGN-SPEC.md.
Resep perubahan

Mengubah kode dengan aman

Menambah kolom ke tab yang ada

Contoh: kolom instagram di tab wisata.

  1. Tambahkan "instagram" di SKEMA.wisata (data.js).
  2. Tambahkan instagram: "" ke setiap baris wisata di data-contoh.js.
  3. Tampilkan di tampilanDetail() (halaman/wisata-detail.js), dengan syarat kosong = tidak tampil: 
    ${item.instagram ? `<p>@${item.instagram}</p>` : ""}
  4. Tambahkan kolom yang sama di Google Sheet (baris judul). Urutan kolom bebas; namanya yang penting.

Menambah tab dan seksi baru

Contoh: tab agenda berisi kegiatan kelurahan, tampil di Beranda.

  1. data.js: 
    agenda: ["judul", "tampil", "tanggal", "tempat"],   // kolom pertama = kunci baris
  2. data-contoh.js: tambahkan agenda: [ { id: "G1", judul: "…", … } ] ke DATA_DUMMY.
  3. index.html: tambahkan seksi dengan wadah kosong: 
    <div id="grid-agenda" class="grid-adaptif" data-maks="3"></div>
  4. halaman/beranda.js: isi wadah itu. 
    isiDariData(document.getElementById("grid-agenda"), "agenda",
  (data) => data.map((a) => `
    <article class="kartu p-5">
      <p class="label-kecil">${a.tanggal}</p>
      <h3 class="judul-kartu mt-2">${a.judul}</h3>
    </article>`).join(""),
  { kosong: "Belum ada agenda.", gagal: "Agenda belum bisa dimuat." }
);
  5. Buat tab bernama persis agenda di Google Sheet, isi baris judulnya, dan format semua selnya sebagai Teks biasa.
  6. Perbarui tab petunjuk di sheet dan tabel di README/Panduan Admin.

Menambah halaman baru

  1. Salin halaman yang mirip (mis. layanan.html) menjadi agenda.html; ganti <title>, kop, dan skrip terakhir menjadi halaman/agenda.js.
  2. Buat assets/js/halaman/agenda.js berisi panggilan isiDariData().
  3. Tambahkan { href: "agenda.html", label: "Agenda" } ke NAV_LINKS di ui.js. Menu dan breadcrumb semua halaman ikut berubah.

Mengganti atau menambah foto

  1. Cara utama tanpa kode: tempel tautan Google Drive di kolom foto pada sheet.
  2. Foto cadangan (tetap tampil bila foto Drive gagal): simpan .webp di img/ dan daftarkan di FOTO (komponen.js) menurut kode barisnya, mis. "danau-linow".
Jangan mengganti nama kolom pertama (nama, jabatan, kunci, …) atau nama tab tanpa mengubah SKEMA di saat yang sama. Google mengirim tab pertama bila nama tab tidak ditemukan; situs menolaknya dan bagian itu menampilkan pesan gagal.
Mencari kesalahan

Saat ada yang tidak tampil

  1. Buka cek-data.html. Halaman ini membaca semua tab lewat muatTab() (data mentah, belum disaring, lengkap dengan nomor baris), menjalankan aturan di ATURAN_TAB (halaman/cek-data.js), dan mencoba membuka setiap foto. Menambah pemeriksaan baru = menambah aturan di sana.
  2. Buka konsol: F12 → Console. Pesan situs berawalan [data] dan menyebut tab serta penyebabnya.
  3. Coba mode contoh: ubah PAKAI_DUMMY menjadi true. Bila masalah hilang, penyebabnya di sheet (akses, nama tab, nama kolom). Bila tetap ada, penyebabnya di kode.
  4. Jalankan di komputer sendiri: halaman harus dibuka lewat server lokal, bukan dobel-klik berkas; alamat file:// membatasi sebagian fitur browser. 
    cd web-lahendong
python3 -m http.server 8000
# buka http://localhost:8000
  5. Periksa data mentah dari konsol: 
    await ambilData("lingkungan")      // array objek yang dipakai situs
await fetch(URL_SHEET.lingkungan).then((r) => r.text())   // CSV mentah dari Google

Menerbitkan

Dari komputer ke GitHub Pages

GitHub Pages menerbitkan cabang main apa adanya. Setiap git push ke main langsung menjadi versi situs yang baru dalam 1–2 menit.

python3 tools/versi_aset.py   # beri penanda versi baru pada CSS/JS yang berubah
git add -A
git commit -m "feat: tambah tab agenda"
git push

GitHub Pages menyuruh browser menyimpan berkas selama 10 menit. Tanpa penanda versi (data.js?v=0cfb573f), browser pengunjung bisa memakai HTML baru dengan JavaScript lama sesaat setelah pembaruan, dan bagian yang bergantung pada perubahan itu gagal dimuat. versi_aset.py mengambil penanda dari isi berkas, jadi hanya berubah bila berkasnya berubah.

Urutan yang aman saat perubahan menyentuh sheet dan kode sekaligus:

  • Menambah kolom atau tab: push kode dulu atau sheet dulu sama-sama aman. Kolom yang belum ada terbaca kosong, tab yang belum ada menampilkan pesan gagal di bagian itu saja.
  • Mengganti nama kolom/tab: siapkan keduanya, ubah sheet, lalu segera push kode. Di antara keduanya bagian itu kosong atau gagal.
  • Setelah mengubah SKEMA atau data contoh: jalankan python3 tools/buat_template.py agar template .xlsx tetap sama dengan situs.
Semua path di situs bersifat relatif (tanpa garis miring di depan, mis. img/emblem.svg), karena situs terbit di sub-folder /web-lahendong/. Pertahankan kebiasaan ini untuk berkas baru.
Panduan ini menjelaskan kode per September 2026. Bila kode berubah, perbarui bagian yang terkait di sini, di README, dan di Panduan Admin.
